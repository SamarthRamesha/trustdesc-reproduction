## Runtime profiles and model selection

Conservative gate: at least 8 GiB GPU and 8 GiB host RAM available. These are planning bounds, not measured guarantees.

**C — high-memory GPU:** explicitly choose `qwen-large` for **Qwen/Qwen2.5-Coder-7B-Instruct**, revision `c03e6d358207e414f1eca0bb1891e29f1db0e242`. A 40 GB-class GPU with at least 32 GiB free recommends profile C; loading the 7B option requires at least 24 GiB GPU and 20 GiB host RAM available. Select a high-RAM runtime too. If insufficient, that model is unavailable; the notebook does not downgrade it. You can explicitly choose the small alternative instead.

**D — original paper display-name configurations:** `paper-claude` = Claude-4.5-Sonnet; `paper-gemini` = Gemini-3-Flash; `paper-gpt` = GPT-5.2; `paper-oss` = gpt-oss-120b. Runtime detection recommends a capacity profile only. It never changes the selected model, temperature, reasoning or dataset silently. ## Execute sections 1–16 in order

1. **Inspect runtime.** Python must be 3.11+. CPU suffices for the default. For inference, select GPU before proceeding, then inspect actual available RAM/disk/VRAM. Do not assume Colab grants a particular device or free quota.

3. **Optional result restore.** For a new run leave false. To resume, upload your own prior result ZIP/checksum. Only data is restored, not code. Use the same project package and source/model settings; a code/config/data/runtime mismatch rejects reuse. Credentials are re-entered, never restored.
4. **Central settings.** Default selects replay. Set model IDs, verified endpoint IDs, caps, seed/temperature and any optional `debloat`/token limits in `MODEL_OVERRIDES`; do not edit source files. Do not put keys in this dictionary.
5. **Dependencies and tests.** CPU plots/UI use `requirements-cpu.txt`; selected GPU paths use the separate proposed pinned GPU requirements only after explicit opt-in/capacity inspection. Package errors are retained; other feasible configurations continue. If Colab requests restart, rerun imports/settings before model work, preserving extraction/results. Core tests run via unittest without overwriting historical reports; their log is stored in the new run.
6. **Acquire/validate inputs.** Default eight synthetic tasks are processed through the existing preparation validator, with input/output hashes and null labels preserved. Source text is staged separately, inspected through AST only. A genuine/reconstructed resource bundle is optional and never silently substituted when selected but invalid/missing.
7. **Credentials/confirmation.** For selected HTTP models, the notebook shows model/endpoint, actual selected tool IDs/origins, transmitted source/description/task/trace scope and persistent request cap. 8. **Run/resume.** Existing runs are detected and listed; choose an index or NEW, then explicitly confirm compatible resume. A new run has a timestamp/UUID. 12. **Condition evaluation.** For every available task, model and original/lite/full condition, the runner passes that condition's descriptions to the agent and records target-call evidence, errors, model calls, latency, tokens and actual cost where provided. Model final answers do not label success. External tasks/configurations record blocked/unavailable statuses and other work continues.

Plot only nonmissing measured values. Runtime overhead uses successful tasks common to all three conditions; unknown cost and zero baselines yield no invented ratio. Read all plot/report scope labels.
15. **Export.** One cell regenerates current analysis and downloads `TRUSTDESC_COLAB_RESULTS.zip` plus `.sha256`. Do this after review and after substantial inference. The archive includes only registered experiment outputs; model caches, personal/unrelated runtime files and credentials are excluded. Checksum/file manifest validation supports later restore and independent Part 3 analysis.

## Checkpoint integrity and recovery

Each operation has a key bound to run fingerprint/stage/model/tool/condition/task contents. State is atomically written before execution. Completed result SHA-256 is verified on reuse. Interrupted work does not acquire a completion marker and retries in a new attempt. Explicit failures remain until you request retry. Requests have pre-call records, cap accounting persists, and partial/errors/raw observations remain available. Different dataset/source/prompt/code/model/config/Python/packages/GPU identity refuses resume. Run directory name is preserved when restoring to keep result/review identifiers stable.

Export is independent of Google Drive. Store the ZIP/checksum on your computer regularly. After disconnect: re-open the same project version, restore your **own** result ZIP, re-acquire identical pinned source text if used, reselect the same settings, re-enter only necessary credentials, confirm resume and continue. Unknown in-flight API billing cannot be recovered; no unsupported “exactly once paid call” guarantee is claimed. Run one notebook/kernel writer per experiment; concurrent writers are not supported.

## Supplied resource bundle contract

`configs/original_benchmark_contract.json` describes the implemented input contract. A ZIP contains exactly one `bundle.json`; source paths are relative to that file and must stay under its directory. Root fields: `origin` (`author_released` or `reconstructed`), nonempty provenance, `sources`, `tools`, `tasks`. Source rows require ref/path/URL/revision/license. Tool rows require unique ID, actual name, source ref, Python language (or explicit unsupported status), optional reviewed `module:function` entry, original description and origin. Task rows require unique ID, valid tool ID and real nonempty text. Author-candidate data must actually contain 52 tools/208 tasks. Provenance remains an operator assertion requiring verification; counts alone do not authenticate a release. All supplied code is forced to the disabled execution backend.

The default source fixture corpus and reconstruction schema do not invent author data. Real-model generated tasks are written separately with model/source-description provenance and hash. Existing original labels do not automatically review new outputs; import review labels only through the current evidence-bound review interface.
